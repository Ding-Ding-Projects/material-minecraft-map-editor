# 更新記錄同離線說明文件基礎

## 狀態同範圍

`amulet_map_editor.api.changelog` 模組係一個唔依賴 wx 嘅資料基礎，由原生
`ChangelogDialog` 使用。桌面「檢視」選單同 `Ctrl+Shift+F` 指令面板會開啟
呢個瀏覽器，提供本機篩選同 Markdown 匯出。儲存庫目前仍然冇聲稱已經有
wx 即時畫面擷取證據；文件講到邊，證據就去到邊，唔會預支掌聲。

隨程式提供嘅 `changelog_catalog.json` 係由記錄喺檔案入面嘅來源修訂可到達嘅
每一個發行標籤產生。每個發行項目會使用標籤名稱、被標記提交嘅日期、完整提交
SHA，同埋未經修改嘅 Git 提交主旨。因此，目錄唔會創作發行文案，亦唔會聲稱
標籤頂端嗰一句主旨就代表完整歷史發行說明。

## 行為

- `load_bundled_catalog()` 會驗證綱要版本 1，並拒絕未知欄位、格式錯誤日期、
  不完整 SHA、重複版本同無效儲存庫連結。
- `filter_changelog()` 會組合包含邊界嘅開始／結束日期、動作分類同文字配對。
  預設係不分大小寫嘅純文字；呼叫者可以為明確正則表達式模式注入專案有界限嘅
  `RegexBuilder` 配對器。
- `available_actions()` 由已載入歷史推導動作選擇器嘅值同數量，唔會維護一份
  越行越偏嘅硬編碼清單。
- `export_markdown()` 匯出傳入嘅畫面，所以已經篩選好嘅結果會保持篩選狀態。
  版本、日期、完整提交目的地同目錄來源修訂都會保留。
- `validate_commit_links()` 接受解析器掛鈎。測試會使用本機 Git 物件查找；
  未來嘅特權應用程式邊界可以提供有界限嘅程式碼託管平台解析器，而唔需要將
  網絡存取塞入展示層。
- `ChangelogDialog` 離線顯示目錄，接受純文字或者明確而有界限嘅正則搜尋，
  將輸入式 ISO 開始／結束日期同可留空嘅原生日曆選擇器配對，以行內方式報告
  無效篩選，並經原生檔案選擇器匯出目前篩選畫面。

## 重新產生目錄

喺儲存庫根目錄執行：

```powershell
py -3 scripts/generate_changelog.py
```

產生器會巡覽可到達標籤，將附註標籤解開到提交，原封不動保留主旨，再寫出
決定性 UTF-8 JSON。動作分類係刻意機械化，而且有清楚文件：

- 以 add／enable／implement／introduce 開始嘅主旨會歸入 `added`；
- fix／repair／correct 會歸入 `fixed`；
- remove／delete／drop／disable 會歸入 `removed`；以及
- 其他所有主旨會歸入中性 `changed` 分類。

原始主旨仍然係顯示同匯出嘅事實；分類只係篩選掛鈎，唔會替歷史改口供。

## 失敗情況

- 新增可到達標籤之後，完整性測試會失敗，直至目錄重新產生並完成審閱。
- 遺失物件或者物件唔係提交，會令提交連結驗證失敗。
- 較新綱要會以 `UnsupportedChangelogVersion` 安全關閉，唔會靜靜雞當佢係
  綱要 1 解讀。
- 無效日期範圍、未知欄位、無效 SHA、過大查詢或者摘要值，會拋出
  `ChangelogValidationError`。
- 空白篩選畫面會匯出明確嘅「冇配對結果」說明，唔會輸出一份似載入失敗嘅
  空文件。

## 保安同私隱

目錄載入同篩選全部喺本機完成，而且唔依賴 wx。模組唔會發出網絡請求、
執行 Git 指令或者寫入使用者資料。產生器係維護工具，會以引數陣列而唔係
shell 呼叫 Git。Markdown 匯出會先逸出由 Git 寫入嘅文字，再用經驗證嘅
HTTPS GitHub 儲存庫網址同完整小寫 SHA 建立提交連結。

## 驗證

執行聚焦測試：

```powershell
py -3 -m unittest -v tests.test_changelog
```

測試會檢查可到達標籤完整性、本機提交物件解析、組合日期／動作／文字篩選、
有界限正則整合、推導動作數量、Markdown 匯出、明確空結果同嚴格綱要拒絕。
呢啲只係來源同單元測試聲明；目前冇作出 wx 執行階段或者畫面擷取聲明。
