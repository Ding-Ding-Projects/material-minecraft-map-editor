# 點心驚喜基礎

## 行為

`amulet_map_editor.api.dim_sum_surprise` 提供同 wx 無關嘅啟動控制器。
每個控制器代表一次應用程式啟動，最多只會進行一次新隨機抽樣。由 `0` 開始、
但唔包括 `0.10` 嘅數值符合資格。首次執行、更新、錯誤或者進行中工作狀態
唔符合資格，會直接無操作。

符合資格嘅抽樣會喺 daemon 執行緒解析圖錄資料，等即時可用嘅外殼返到事件迴圈後，
先投影一個安全焦點、非模態 `DimSumSurpriseToast`。啟動過程冇確認、購買、
評論、評分、捐款或者其他宣傳關卡。通知禁止搶焦點，八秒後自動關閉，並按照
英文、粵語或者雙語模式，本地化權威點心名稱同有意義圖片替代文字。圖錄遺失／
離線、School mode、更新／錯誤狀態，或者使用者已經開咗世界，都會保持安靜
無操作。啟動控制器只用一次，所以同一次應用程式執行永遠唔會抽兩次。

## 公開來源同相片界線

點心中繼資料只會由標準公開圖錄擷取：

`https://raw.githubusercontent.com/Ding-Ding-Projects/dim-sum-photos/main/catalog/index.json`

要求最多等三秒，回應上限八 MiB。只接受 schema `1.0.0`，而且記錄入面
`name.en`、`name.zhHant`、圖片替代文字，同安全 `images/*.png` 圖錄路徑
都必須有界限。網絡、逾時、解碼、schema 同選擇失敗都只會令驚喜唔出現，
所以離線啟動仍然完全可用。

呢個消費者儲存庫唔會產生、下載、內置或者快取相片檔案。原生通知會如實提供
圖錄圖片資產路徑同替代文字，唔會扮成已經擷取圖片。未來圖片解析器必須將路徑
同已發佈 `catalog-v1*` 發行資產核對，而資產必須來自
`Ding-Ding-Projects/dim-sum-photos`，
之後使用公開資產網址，或者呢個儲存庫以外嘅應用程式資料快取。

## 保安同失敗情況

- 來源網址係固定 HTTPS，重新導向變更會被拒絕。
- JSON 解碼之前，會由 `Content-Length` 同實際有界限讀取兩邊檢查回應大小。
- 不可信圖錄字串同路徑都有清楚長度同形狀界限。
- 只有揀到有效點心之後先會呼叫背景回呼。
- wx 投影會經 `CallAfter` 排程，永遠唔會模態執行或者要求焦點。
- School mode、更新／錯誤狀態，或者有進行中世界編輯分頁時，會抑制原生投影。
- 任何回呼或者背景解析失敗，都會保持啟動安全嘅無操作。

## 驗證

執行：

```powershell
py -3 -m unittest tests.test_dim_sum_surprise -v
```

測試包括精確機率界線、並行安全單次觸發狀態、三種語言模式、有界限圖錄解析、
離線失敗，同埋消費者儲存庫冇點心圖片副本。
