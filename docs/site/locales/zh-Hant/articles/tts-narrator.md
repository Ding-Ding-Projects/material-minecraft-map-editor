# 可選 TTS 旁白

同 wx 無關嘅 `amulet_map_editor.api.tts_narrator` 模組提供自願啟用嘅
語音事件佇列。佢刻意保持做一條細小整合界線：應用程式可以宣讀更新、儲存或者
錯誤，而唔會令事件流程依賴語音套件、網絡連線或者可見對話框。

## 行為

- 旁白**預設關閉**，並喺資料檔 `amulet_tts_narrator` 持久化。
- 語言選擇係 `english`、`cantonese` 或者 `both`。用 `both` 時，
  英文語句講完先會開始粵語語句。
- 所有事件經同一個工作程序順序處理。同一類別有較新事件時，會取代較舊嘅
  排隊事件，避免一次過讀出一堆過期通知。
- 短暫防彈跳會將快速更新合併。有界限嘅逐類別冷卻時間會減少重複進度訊息，
  同時保留最新事件。
- 英文同粵語幽默程度只會改變周邊語氣。事件文字同所有事實細節仍然由呼叫者提供。

## 設定

`load_settings()`、`save_settings()` 同 `update_settings()` 會驗證
版本化設定記錄。冷卻時間限制喺 0–3600 秒，防彈跳限制喺 0–10 秒。
旁白語言同設定獨立於應用程式套件身分同更新 feed。

應用程式會注入一個 `SpeechBackend`，當中有同步 `speak(text,
language)` 方法。`default_backend()` 刻意傳回
`NullSpeechBackend`：呢個檢出版本唔會聲稱有粵語語音、唔會安裝可選語音
相依項，而且除非使用者已啟用旁白，否則永遠唔會發聲。

## 失敗同保安界線

後端例外會寫入記錄，但唔會打斷原本操作。佇列只會喺記憶體保留有界限事件文字，
設定就留喺現有本機資料檔；唔會儲存語音憑證、音訊、遙測或者網絡回應。
`close()` 會清除待處理事件，再加入工作程序，令應用程式可以安全關閉。
螢幕閱讀器協調同平台語音選擇屬於未來原生轉接器；喺嗰啲能力可用之前，
無操作後端係誠實嘅後備方案。

## 驗證

執行同 wx 無關嘅測試套件：

```powershell
python -m unittest -v tests.test_tts_narrator
```

測試包括預設關閉嘅持久化同界限、同類別防彈跳／取代、順序雙語次序、冷卻期
保留最新事件、幽默程度樣式，同埋後端不可用時嘅無操作路徑。
